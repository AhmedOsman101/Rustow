# ADR 0006: `husky-rs` stays a regular (runtime) dependency

- **Status:** Accepted (2026-11-16)
- **Context:** Code review (F11) found `husky-rs` declared as a regular dependency, referenced nowhere in `src/` or `tests/`, and asked whether it was intentional. `AGENTS.md` already declared it intentional ("the user's git-hooks tooling — theirs, leave it alone"), but the *why* was undocumented. Reading the crate's documentation (https://github.com/pplmx/husky-rs) shows what it actually does.
- **Decision:** Keep `husky-rs` exactly as declared. It is a build-time hook installer: the `build.rs` inside the crate itself sets `core.hooksPath` to `.husky/` on `cargo build` / `cargo test` (docs: "Automatic installation — Hooks configure on cargo build or cargo test"; hook installation is skipped only via its own `NO_HUSKY_HOOKS=1`). The `.husky/pre-commit` script is plain bash; rustow's source never calls into the crate. As a *regular* dependency it is active for every checkout/build — which is the point of a repo-local hook. This ADR plus a line in AGENTS.md is the documentation the review asked for; the crate stays until the owner of the hook tooling says otherwise.
- **Consequences:** Positive — the mechanism is now recorded; review verdict settled; no confusion in future audits. Negative — one always-linked crate whose presence only makes sense at build time; accepted as the cost of the zero-config hook install.
