# rustow v0.2.0 — Review fixes, gaps, migration, root targeting — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use /subagent-driven-development (recommended) or /executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every verified finding from the whole-tree review, close the approved items from the coverage report (§5.1/§5.2), land per-package `includes` and root targeting, and add `rustow config migrate` — as one v0.2.0 line.

**Architecture:** Narrow plan file that references the spec and ADRs instead of duplicating them. Work is ordered: code-review fixes first (they touch the same conflict/link machinery everything else builds on), then coverage/docs items, then the three feature axes (config `includes`, root targeting + elevation, `config migrate`), then proptest and the PTY harness. Each task is a vertical slice: schema → behavior → tests → commit.

**Tech Stack:** Rust (edition 2024), clap, schemars, dialoguer, proptest (new dev-dep), PTY crate for the spike (see Task 24), existing `mask` task runner.

**Spec:** `docs/spec.md`, `docs/reports/2026-11-11-v1-report.md` (sections §5.1, §5.2, §6.3, §7 as of 2026-11-11 — those items are resolved below), `docs/code-review/2026-11-16-rustow-extensive.md`, ADRs `docs/adr/0001-root-targeting.md` … `0008-profiles-future.md` (the design law for the new features; read all eight before Task 16).

## Global Constraints

- Never operate against the real `$HOME`, never with a real `~/.stowrc`; every test fixture uses a tempdir and isolated `HOME`/`XDG_CONFIG_HOME`/`XDG_CACHE_HOME`/`DOTFILES_DIR`/`DOTFILES_TARGET`.
- `mask check` (fmt + clippy `-D warnings` + all tests) green before every commit.
- Config model changed ⇒ regenerate `schema.json` via `mask schema` and keep `docs/config.toml` identical to `rustow config default` (the `schema_fresh` test enforces both).
- Conventional Commits; one logical slice per commit; no `--no-verify`.
- Review findings are evidence, not gospel: **verify each F-finding reproduces before changing code; if it doesn't reproduce, drop it and record why in this plan's Appendix.**
- `husky-rs` stays exactly as is (ADR 0006).
- The Windows targets remain Unix-like-only documentation-wise (ADR 0007); no pipeline changes.

## Review Focus

Five input classes most likely to bite, most likely first:

1. **A root-mapped link fails mid-apply** (`/etc/snapper/configs` not writable) — must abort before any filesystem change. Task 20 owns this; test asserts zero filesystem delta on failure.
2. **A stowrc that parses but points at a moved directory** — `config migrate` must error cleanly, never write a config pointing at nothing. Task 22 pins this.
3. **Per-package `includes` that hides everything** (`!**`) — legal config, results in an unlinkable package; `status` must show it honestly. Task 17 pins behavior, not editorial flavor.
4. **Interactive prompt with EOF/closed stdin** (not a TTY but not `-n` either) — must abort cleanly with nothing applied; no panic. Tasks 20 / 22 pin both.
5. **`--as-root` with `--dry-run`** — dry-run wins; nothing is applied, nothing is elevated. Task 20 pins this.

Every one of those gets a dedicated test in the task that owns it.

**Plan complete and saved to `docs/plans/2026-11-16-gaps-v020.md`, with ADRs under `docs/adr/`. Please review the plan. Which execution approach would you prefer?**

- **Subagent-driven** - A fresh subagent implements each task and a fresh reviewer checks it before the next one starts, then a whole-branch review at the end. Most thorough; costs a fresh context per task and per review.
- **Native** - I implement every task myself in this session, then one fresh reviewer on the most capable model checks the whole branch. Cheapest and fastest; no independent review until the end.

For this plan I recommend **Subagent-driven**, because the tasks mutate the same core files (`src/link.rs`, `src/config.rs`, `src/status.rs`) and a per-task gate after each one catches semantic drift that a single end-of-branch review reaches too late.
